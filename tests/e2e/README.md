# 브라우저 자동 테스트 (T-32·T-33)

실제 dev Supabase와 화면을 연결해 PC(1440px), 모바일(390px)에서 같은 시나리오를 실행한다. 서버·DB를 흉내 내지 않는다. Node.js 24가 필요하다.

## 준비와 실행

1. `.env.local`에 **dev** URL·Publishable key를 설정한다.
2. `.env.test.example`을 `.env.test.local`로 복사하고 dev의 테스트 전용 계정 A·B와 `E2E_DEV_PROJECT_REF`를 설정한다. E2E는 A를 사용한다. 일반 사용자 계정·운영 프로젝트는 사용하지 않는다.
3. 실행한다. 4173 포트는 자동으로 시작·종료되므로 비워 둔다.

```bash
nvm use 24
npm ci
npx playwright install chromium
npm run test:e2e

# 설치된 Google Chrome 사용 (최신 번들 브라우저를 지원하지 않는 macOS 13 등)
E2E_CHROME=1 npm run test:e2e

# 한 화면 크기·시나리오만 실행
E2E_CHROME=1 npm run test:e2e -- --project=mobile --grep '식단 계획'
# 브라우저를 보면서 실행
E2E_CHROME=1 npm run test:e2e -- --project=desktop --headed
```

Playwright의 모바일 설정은 Chrome 화면 크기·터치 에뮬레이션이다. 실제 iPhone Safari의 사진 보관함·HEIC 선택 검증을 대신하지 않는다. 이메일 코드 발송·SMTP와 운영 성능 검증은 T-35에서 실제 설정과 함께 확인한다.

## 데이터와 중단 복구

- `E2E_DEV_PROJECT_REF`와 접속 URL이 다르면 실행하지 않는다. CI에서는 실행을 차단한다. 이메일 코드를 발송하지 않고 Node에서 A로 비밀번호 로그인한 세션을 새 브라우저에 주입한다. 세션 파일은 만들지 않는다.
- worker는 1개이며 PC·모바일을 순서대로 실행한다. 실행 중에는 계정 A를 직접 쓰거나 DB 통합 테스트를 함께 실행하지 않는다.
- 실행 전 A의 전체 기록·원래 사진을 `.e2e-recovery/snapshot.json`에 보관한다(로컬 전용, 권한 600, Git 제외). 사진이 20MiB보다 많거나 보관에 실패하면 변경을 시작하지 않는다. 테스트마다 가명 상태로 초기화한다.
- 성공·실패 모두 종료 시 임시 사진을 정리하고 원래 기록·사진 경로를 복구·검증한 뒤 복구 파일을 지운다. 복구 오류가 나면 파일을 남긴다. 복구 파일에는 원래 테스트 데이터와 사진이 들어 있으므로 공유하지 않는다.
- 강제 종료 등으로 파일이 남으면 같은 dev 계정 설정으로 아래 명령을 실행한다. 살아 있는 다른 E2E 프로세스가 있으면 복구를 시작하지 않는다. 복구가 확인되기 전에는 파일을 지우지 않는다.

```bash
npm run test:e2e:recover
```

자동 trace·video·screenshot은 끄고 결과 폴더도 Git에서 제외했다. 실패 메시지에 원래 백업 내용을 덤프하지 않는다. 테스트용 다운로드는 Playwright 임시 폴더에서 종료 시 정리한다.
