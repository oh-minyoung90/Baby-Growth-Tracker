# 화면 오류 검증

2026-11-18 · iPhone 수면 시간 입력칸·승인된 홈 시안 검증.

화면 오류를 사용자가 모든 페이지에서 찾아야 하는 방식으로 운영하지 않는다. 기능 테스트와 별도로
브라우저에서 실제 요소의 크기·겹침·넘침을 검사하며, 발견한 오류를 재발 방지 시나리오에 추가한다.

## 이번 수정

iPhone 화면에서 밤잠의 두 시간 입력칸이 겹치고 카드 밖으로 나왔다. iOS 날짜·시간 컨트롤의 기본
외형과 padding이 너비 계산에 영향을 주는 문제는 [WebKit 보고 #301648](https://bugs.webkit.org/show_bug.cgi?id=301648)에도
있다. Mac Chrome·WebKit의 기존 native 입력에서는 첨부 화면과 같은 현상이 그대로 재현되지 않았다.

공통 `TimeInput`을 추가해 기존 `DateInput`처럼 **표시 영역과 기기의 기본 선택 입력을 분리**했다.
표시 영역의 크기는 CSS로 정하고, 투명한 실제 `input[type=time]`은 기본 외형·padding을 제거해 그
영역 안에 둔다. 빈 칸은 ‘시간 선택’, 입력값은 `21:30`처럼 표시한다. 밤잠과 낮잠에 모두 적용했다.
기본 시간 선택·라벨·포커스·오류 연결·저장 값·수면 계산 규칙은 유지한다.

## 자동 검사

```bash
nvm use 24
npx playwright install chromium webkit
npm run test:ui
# 설치된 Chrome만 실행
E2E_CHROME=1 npm run test:ui -- --project=chromium
```

- `playwright.ui.config.ts`·`tests/ui/`: 실제 홈·수면 입력 라우트를 사용한다. 인증·가명 API 응답은 `fixture.ts`에서 준비한다.
- 실제 DB·계정 없이 가명 Auth 세션과 화면에 필요한 아이·기록 응답만 제공한다. 허용하지 않은 외부 요청은
  차단하고, 실제 로그인·저장 요청은 하지 않는다. `.env.local`·`.env.test.local`이 없어도 실행한다.
- Chromium·WebKit × 320/375/393/430/768/1440px × 라이트/다크 = **24개 조건**.
  768px 미만은 모바일·터치 컨텍스트를 사용한다.
- 빈 값·밤잠 입력·낮잠 추가/입력/삭제·오류 문구 표시·계산 합계·값 지우기를 실행한다.
- 페이지 가로 넘침, 입력칸끼리 겹침, 입력칸의 부모/화면 밖 넘침, 터치 영역 44px 미만,
  표시값 불일치·글자 잘림을 검사한다. 페이지 전체 너비만 보는 검사로는 카드 안 겹침을 놓칠 수 있다.
- CI에 브라우저 설치·`test:ui` 작업을 추가했다. 실제 Supabase를 쓰는 `test:e2e`는 기존대로 로컬에서
  별도로 실행한다. 자동 trace·영상·스크린샷은 만들지 않는다.

## 확인 범위와 한계

로컬에서는 Chrome 및 macOS 13에서 실행 가능한 WebKit 18에서 같은 검사 함수를 사용했다.
WebKit 18은 임시 호환 도구로 실행했으며 프로젝트 의존성을 하향하지 않았다. CI는 저장소에 고정된
Playwright와 해당 Chromium·WebKit을 설치한다. 로컬 WebKit 에뮬레이션을 실제 iPhone 확인과 동일하게
표시하지 않는다.

이번 자동 검사의 범위는 **홈·수면 입력 화면**이다. 모든 화면의 미관·글자색·가상 키보드·iOS 버전별
기본 선택창이나 카카오톡 인앱 브라우저까지 완벽하게 판정하지는 못한다. 화면별 검사를 점차
늘리고, 실제 기기 확인은 배포 후 대표 흐름 및 자동화로 재현하기 어려운 문제에 집중한다.
이번 수정의 실제 iPhone·인앱 브라우저 확인은 배포 후 남아 있다.

2026-11-16 로컬 결과: Chrome 12조건·WebKit 18 12조건 통과, 기존 단위/컴포넌트 598개 및 실제
dev DB의 수면 E2E PC·모바일 2개 통과. 원래 테스트 기록 복구와 lint·format:check·typecheck·build도
확인했다. CI 작업은 설정을 추가한 상태이며 원격 실행 결과는 PR에서 확인한다.

## 홈 시안 반영 (2026-11-18)

- `homeLayout.ts`·`home-layout.spec.ts`: 6개 폭 × 라이트/다크 × 2개 엔진의 24조건과 320/1440px 빈 홈 4조건을 추가한다. 기존 수면 24조건과 합쳐 **52조건**이다.
- 가명 발달·수면·측정·식단을 제공하고 긴 음식 이름이 줄바꿈되는 경우도 확인한다. 실제 데이터는 읽거나 쓰지 않는다.
- 식단 → 오늘 기록 → 수면 → 측정 → 빠른 기록 순서, 모든 카드 폭·시작점·별도 행, 제목 16px·아이콘 20px·대표 값 14px, 빠른 기록 3개 동일 폭·실선·식단과 같은 보조 배경, 주 메뉴 순서를 검사한다.
- 성장 선택 시트의 네 항목·화면 밖 넘침·취소 후 초점 복귀도 확인한다. 빈 홈에서는 “오늘 성장 기록하기”와 빠른 기록의 성장 버튼을 각각 검사한다. 유형 선택·입력 취소 후 홈 복귀와 조회 오류 재시도는 컴포넌트 테스트가 맡는다.
- Chrome 26조건·WebKit 18 26조건을 로컬에서 확인했다. macOS 13 호환용 WebKit은 임시 폴더에서 실행하며 프로젝트 의존성은 그대로다. 실제 iPhone의 최종 배포 화면 확인은 별도로 남아 있다.

## 성장 기록 시안 반영 (2026-11-19)

- `timelineLayout.ts`·`timeline-layout.spec.ts`: 320/393/768/1440px × 라이트/다크 × Chromium/WebKit의 16조건을 추가한다. 기존 홈·수면 52조건과 합쳐 CI에서 68조건을 검사한다.
- 누적 카드 4개·2열/4열 배치·모바일 52px·누적 카드의 겹침/잘림/넘침, 중복 유형 칩 제거, 카드·목록의 노란 음식 아이콘을 검사한다.
- 카드 선택/재선택/전체 보기가 기간·직접 지정한 날짜를 유지하고, 개수는 누적으로 남는지 확인한다. 키·몸무게 탭으로 이동해 측정이 보이는지도 확인한다.
- 실제 계정·DB 없이 가명 API 응답만 사용한다. 공유 주소 복귀·이전 유형 주소 호환·음식 날짜 변경/제거·조회 오류 재시도는 단위·컴포넌트 테스트로 확인한다.

2026-11-19 로컬 결과: 성장 Chrome 8조건·WebKit 18 8조건, 단위·컴포넌트 604개, lint·format:check·typecheck·build 통과. 실제 iPhone 배포 화면 확인은 머지 후 진행한다.

### CI 설치 지연과 실행 한도 (2026-11-19)

PR #116의 첫 CI는 Ubuntu 패키지 미러 다운로드 지연으로 브라우저·시스템 의존성 설치에 약 8분 48초가 걸렸다. 화면 검사 27개는 통과했지만 작업 전체의 10분 한도에 도달해 취소됐다. GitHub 체크 주석의 `The job has exceeded the maximum execution time of 10m0s`로 원인을 확인했다.

브라우저 작업의 실행 한도를 20분으로 늘려 설치와 전체 68개 검사를 마칠 시간을 확보한다. 코드·빌드 작업의 한도는 기존 10분이다.
