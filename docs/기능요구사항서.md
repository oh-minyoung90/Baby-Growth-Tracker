## 1. 개요

### 1.1 목적

PRD v1.0에서 정한 기능(F-01~F-24)을 화면 단위로 구체화한다. 화면별로 무엇을 보여주고, 무엇을 입력받고, 어떻게 반응하는지 정의해 구현과 테스트의 기준으로 삼는다.

### 1.2 범위

| 구분 | 작성 수준 |
| --- | --- |
| MVP-1 (성장 기록, 공통 기능) | 상세 (4장) |
| MVP-2 (식사 기록) | 개요 (6장). PRD에서 확정된 규칙만 정리하고, 화면 상세는 MVP-1 구현 후 작성 |
| 2차·3차 기능 | 제외 |

### 1.3 기준 문서

- `PRD.md` v1.1. 이 문서와 PRD가 다르면 PRD를 따르고, 차이는 8장에 올려 승인을 받은 뒤 두 문서를 함께 고친다.

### 1.4 용어

| 용어 | 뜻 |
| --- | --- |
| 기록 날짜 | 사용자가 기록에 지정한 날짜(`date`). 입력한 시각(`createdAt`)과 다르다 |
| 오늘 | 사용 중인 기기의 현재 시각 기준 날짜 |
| 생후 일수 | 생년월일과 기록 날짜로 계산한 "생후 N개월 N일" |
| 발달 기록 | 단어, 행동, 표정, 놀이 4가지 유형의 기록 (Milestone) |
| 수면일 | 수면 기록의 기준 날짜. 밤잠에 든 날 |
| 계획 칸 / 먹음 칸 | 주간 식단에서 "먹음" 체크를 하지 않은 칸 / 체크한 칸 (MVP-2) |

### 1.5 요구사항 ID 규칙

- 화면: `SCR-번호` (예: SCR-05)
- 기능 요구사항: `FR-화면코드-번호` (예: FR-MS-03 = 발달 기록 화면의 3번째 요구사항)
- 비즈니스 규칙: `BR-번호`
- 모든 FR에는 대응하는 PRD 기능 ID(F-xx)를 함께 적는다.

### 2.2 메뉴 구조

하단 탭 5개로 구성한다. MVP-1에서는 "식사" 탭을 숨긴다.

```
┌─────────────────────────────────────────┐
│                (화면 영역)                │
├────────┬────────┬────────┬────────┬────────┤
│   홈   │  성장  │ 타임라인 │  식사  │  설정  │
└────────┴────────┴────────┴────────┴────────┘
  SCR-03   SCR-04/  SCR-07   SCR-10~  SCR-09
           06/08            12(MVP-2)
```

- **성장** 탭 안에서 상단 탭으로 "키·몸무게 / 단어 / 수면"을 전환한다. 행동·표정·놀이는 타임라인에서 본다.
- 발달 기록 입력(SCR-05)은 홈의 빠른 기록 버튼, 타임라인, 단어 목록에서 연다.

```
앱 실행

        │ 예                         │ 성공
        ▼                            ▼
  아이 정보가 있는가? ── 아니오 → SCR-02 아이 정보 등록 (최초 1회)
        │ 예                         │ 저장
        ▼                            ▼
      SCR-03 홈 ◀────────────────────┘
        ├─ 빠른 기록 → SCR-05 발달 입력 / SCR-08 수면 입력 / SCR-04 키·몸무게 입력
        ├─ 하단 탭 → 성장 / 타임라인 / 설정
        └─ 저장·취소 후에는 진입했던 화면으로 돌아감
```

## 3. 공통 규칙

### 3.1 날짜와 시간대

| ID | 요구사항 | F-ID |
| --- | --- | --- |
| FR-COM-01 | "오늘"은 기기의 현재 시각 기준 날짜로 판단한다. | F-03 |
| FR-COM-02 | 모든 기록의 날짜 입력 기본값은 오늘이다. 과거 날짜를 선택할 수 있다. | F-03 |
| FR-COM-03 | 오늘 이후 날짜는 선택할 수 없다 (MVP-2 주간 식단은 예외). | F-03 |
| FR-COM-04 | 생년월일 이전 날짜는 선택할 수 없다. | F-03 |
| FR-COM-05 | 날짜는 `YYYY. M. D. (요일)` 형식으로 표시한다. 예: 2026. 10. 14. (수) | - |

### 3.2 생후 일수 계산

- 표시 형식: `생후 N개월 N일`. 0개월이면 `생후 N일`로 표시한다.
- 계산: 생년월일에서 개월 수를 더해 가며, 기록 날짜를 넘지 않는 가장 큰 개월 수를 N개월로 한다. 남은 날수가 N일이다.
- 다음 달에 생일과 같은 날짜가 없으면 그 달 말일을 기준일로 본다.

| 생년월일 | 기록 날짜 | 표시 |
| --- | --- | --- |
| 2026-01-15 | 2026-01-15 | 생후 0일 |
| 2026-01-15 | 2026-03-20 | 생후 2개월 5일 |
| 2026-01-31 | 2026-02-28 | 생후 1개월 0일 |
| 2026-01-31 | 2026-03-01 | 생후 1개월 1일 |
| 2026-01-31 | 2026-03-31 | 생후 2개월 0일 |

- 생후 일수는 저장하지 않고 화면에서 계산한다. 생년월일을 수정하면 모든 기록의 표시가 바뀐다.

### 3.4 메시지와 확인 창

| 상황 | 방식 | 예시 문구 |
| --- | --- | --- |
| 저장 성공 | 화면 하단에 2초간 짧은 알림 | "저장했어요" |
| 입력 오류 | 해당 입력칸 바로 아래 빨간 문구 + 아이콘 | "키는 30~150cm 사이로 입력해 주세요" |
| 삭제 | 앱 자체 확인 창 (브라우저 기본 alert 사용 안 함) | "이 기록을 삭제할까요? 삭제하면 되돌릴 수 없어요" [취소] [삭제] |
| 중복 기록 | 앱 자체 확인 창 | "이미 기록된 내용입니다 (2026. 9. 3.)" [취소] [그래도 저장] |
| 네트워크 오류 | 화면 상단 안내 + 다시 시도 버튼. 입력 중인 내용은 유지 | "저장하지 못했어요. 인터넷 연결을 확인해 주세요" |

- 오류는 색상만으로 구분하지 않고 아이콘과 문구를 함께 쓴다.

- MVP에서는 오프라인 입력을 지원하지 않는다. 인터넷에 연결되지 않으면 저장할 수 없고, 3.4의 네트워크 오류 안내를 표시한다.

│  [ 인증 코드 받기 ]         │
│                            │

| ID | 요구사항 | F-ID |
| --- | --- | --- |

| FR-AUTH-03 | 코드 유효 시간과 재발송 제한을 화면에 표시한다. 구체적인 값은 Supabase 설정에 따른다 (확인 필요). | F-12 |
| FR-AUTH-04 | 코드가 틀리거나 만료되면 "코드가 맞지 않거나 만료되었어요"를 표시한다. | F-12 |
| FR-AUTH-05 | 로그인에 성공하면 로그인 상태를 기기에 유지한다. 로그아웃은 설정(SCR-09)에서 한다. | F-12 |
| FR-AUTH-06 | 로그인하지 않은 상태에서는 SCR-01 외의 화면과 데이터에 접근할 수 없다. | F-12 |

## 8. 결정 사항 및 미결정 항목

### 8.3 작성 중 새로 나온 항목

### 8.5 미결정: 확인 필요 (기술요구사항서에서 확인)

- 이메일 인증 코드의 유효 시간과 재발송 제한 (Supabase Auth 설정값)
- 허용 이메일만 코드를 받도록 하는 구현 방법 (Supabase에서 회원가입 차단 + 허용 계정만 사전 등록)
- 서버에서 "오늘 이후 날짜"를 검증하는 방법 (서버는 기기 시간대를 모름)
- 가져오기의 전부 성공 또는 전부 실패 처리 (DB 트랜잭션)
