# 준비 목록

2026-11-24 승인 시안 구현. 기존 사야 할 물건을 확장해 **해야 할 일 → 사야 할 물건** 순서로 묶는다.

## 화면

- `/preparation`은 해야 할 일을 기본으로 연다. `/shopping`은 기존 링크·주소와 카테고리·자주 사는 물건 상태를 유지한다. 두 화면의 상단은 공통 제목 **준비 목록**, 탭은 **해야 할 일 / 사야 할 물건**이다.
- 홈의 어젯밤 수면 다음 카드를 **준비 목록**으로 바꾸고 **할 일 N개 · 살 물건 N개 ›**로 표시한다. 완료한 일·구매 완료·보관 전용 물건은 개수에서 제외한다. 어느 조회든 실패하면 0개로 오인시키지 않고 오류·재시도를 제공한다. 홈에서 들어가면 할 일이 먼저 열린다.
- 모바일 하단 메뉴의 마지막 칸은 항상 **준비**다. 모바일의 환경 설정은 홈과 아이 정보 헤더에서 열며, PC 왼쪽 메뉴는 준비와 설정을 모두 제공한다.
- 물건 화면의 살 물건 / 자주 사는 물건 선택은 기존 알약 필터로 이동한다. 카테고리는 음식 / 의류 / 생활용품 / 장난감 / 도서 / 기타를 유지한다.

## 할 일

제목 필수 80자, 마감일 선택(미래 날짜 허용·지우기 제공), 메모 선택 500자, 관련 링크 선택 2,048자. 마감일이 있는 항목부터 오름차순, 마감일 없으면 뒤에 표시하고 같은 날짜에서는 최근 수정순으로 정렬한다. 알림 발송·반복 일정은 이번 범위에 없다.

체크하면 완료한 일 영역으로 이동한다. 완료 영역은 기본 접힘이며 체크 해제로 되돌린다. 제목을 눌러 수정·삭제 확인을 제공한다. 내용 수정은 완료 상태를 덮어쓰지 않는다. 조회·체크·저장 오류를 구분하고, 저장 실패 시 입력을 유지한다. 체크 실패는 해당 항목의 동일 작업만 재시도한다.

링크는 HTTP(S)만 허용하며 실행 스킴·공백·인증정보가 포함된 주소는 거부한다. 외부 페이지는 미리 불러오지 않고 새 탭에서 `noopener noreferrer`로 연다.

## DB와 백업

`preparation_tasks`: id, owner_id, name, due_date, memo, url, completed, created_at, updated_at. 소유자 기본값은 auth.uid(), 본인만 조회·추가·수정·삭제하도록 RLS와 DB 길이·URL 제약을 둔다. 다른 계정으로 소유자 변경도 거부한다.

JSON 백업 v3은 할 일을 포함한 14개 테이블을 내보낸다. v1·v2는 기존 전체 교체 의미대로 빈 할 일 목록으로 확장하며, v3의 할 일 누락·잘못된 날짜·위험한 URL은 거부한다. DB 복원과 전체 삭제는 할 일까지 같은 트랜잭션에서 처리한다. 큰 파일의 ID 변환은 테이블별 ID 맵을 한 번 펼친 뒤 관계형 조인으로 변환한다. 진단 중 사용한 함수별 JIT 설정은 ID 조인 마이그레이션에서 기본값으로 되돌린다. 발달 기록 INSERT는 문장 단위 중복 검사로 묶어 대량 복원 지연을 줄이고, UPDATE는 기존 중복 검사와 과거 기록 수정 규칙을 유지한다.

마이그레이션 `20261124010000_preparation_tasks.sql`, `20261124020000_backup_task_batch_map.sql`, `20261124030000_backup_import_no_jit.sql`, `20261124040000_backup_id_map_join.sql`, `20261124050000_milestone_insert_batch_validation.sql`을 dev 프로젝트에 적용했다. 운영 DB와 운영 배포는 아직 변경하지 않았다. 배포 시 다섯 마이그레이션을 먼저 적용해야 한다.
