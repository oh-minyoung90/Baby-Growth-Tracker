# 쇼핑 리스트 — 승인된 시안 구현

2026-11-23 · 사용자 승인. 화면 모양은 기존 디자인 토큰·ChoiceChips·FormPage를 사용한다.

## 화면과 동작

- 홈 상단에 작은 쇼핑 리스트 바로가기와 미구매 개수를 표시한다. 조회 중·실패 시 실제 0개처럼 표시하지 않는다.
- `/shopping`의 두 탭은 살 물건 / 자주 사는 물건이다. 탭과 카테고리는 주소에 저장해 수정·취소 후 유지한다.
- 카테고리는 전체 / 음식 / 의류 / 생활용품 / 장난감 / 도서 / 기타. 드롭다운 대신 기존 알약 필터를 사용하고 모바일에서 줄바꿈한다.
- 살 물건의 구매 체크는 완료 영역으로 옮기며, 완료 영역은 기본 접힘이다. 체크를 해제하면 살 물건으로 돌아온다.
- 자주 사는 물건은 링크를 보관한다. 다시 담기는 같은 항목을 미구매로 전환해 중복을 만들지 않는다. 이미 미구매라면 목록에 있음으로 표시하고 중복 실행을 막는다.
- 이름을 누르면 수정한다. 물건 이름(필수, 80자), 카테고리, 구매 링크(선택, 2,048자), 메모(선택, 500자), 자주 사는 물건 보관 여부를 입력한다. 링크는 언제든 추가할 수 있다.
- 자주 사는 물건 탭에서 새로 추가하면 보관 전용이며 구매 목록에는 넣지 않는다. 보관 전용 항목은 항상 자주 사는 물건이며, 해제하려면 삭제 확인을 거친다. 구매 중·완료 항목은 수정에서 보관을 켜고 끌 수 있다.
- 삭제 확인은 살 물건·완료·자주 사는 물건에서 같은 항목이 함께 삭제됨을 알린다. 구매 횟수·개별 구매 이력은 이번 범위에 포함하지 않는다.
- 링크는 HTTP(S)만 허용하고 사용자명·비밀번호가 든 URL, 공백, 다른 실행 스킴은 거부한다. 외부 페이지를 미리 가져오지 않고 `noopener noreferrer` 새 탭 링크로만 연다.
- 로딩·오류·빈 결과를 구분한다. 저장 실패는 입력값 유지, 체크 실패는 동일 항목 재시도, 요청 중 중복 조작 방지를 제공한다.

## 메뉴 설정

기본 모바일 메뉴는 홈 / 식사 / 성장 / 수면 / 설정이다. 설정의 하단 메뉴에 쇼핑 표시를 켜면 마지막 칸은 쇼핑이 되고, 기본 화면 제목 오른쪽 톱니바퀴로 설정에 접근한다. 끄더라도 홈·설정의 쇼핑 바로가기는 유지된다. PC 왼쪽 메뉴에는 쇼핑과 설정을 모두 둔다.

메뉴 선택은 화면 모드와 같이 브라우저에 저장한다. 계정별 키 `bgt-shopping-tab:<user-id>`를 사용해 다른 계정에 설정이 섞이지 않으며, 저장소가 막혀도 현재 화면에서는 적용한다. 이 기기 설정은 JSON 기록 백업 대상이 아니다.

## 저장·보안·백업

`shopping_items`는 `id`, `owner_id`, `name`, `category`, `url`, `memo`, `is_frequent`, `status`, `created_at`, `updated_at`를 저장한다. `status`는 pending(미구매), purchased(완료), saved(보관 전용)이다. saved는 is_frequent=true여야 한다. 수정 API는 상태를 덮어쓰지 않아 다른 탭의 구매 체크를 보존한다. 모든 접근은 owner_id RLS로 본인만 허용하며 타인 owner_id로 추가·변경하지 못한다.

백업 형식 v2에는 쇼핑을 포함한 13개 테이블이 들어간다. v1 파일도 허용하며 쇼핑 목록이 없는 전체 교체로 해석한다. v2의 쇼핑 누락·위험한 URL은 거부한다. 전체 삭제도 쇼핑과 기존 기록을 같은 DB 트랜잭션으로 삭제한다. 가져오기에서 타인 ID 충돌을 다시 발급하고 원자적으로 복원한다.

## 적용

마이그레이션 `20261123050154_shopping_list.sql`은 dev에 적용했다. 운영에는 아직 적용하지 않았다. 운영 배포 시 이 마이그레이션과 프론트엔드 변경을 함께 적용해야 한다. 새 백업 v2는 이전 프론트엔드에서 상위 버전 안내가 나오므로 운영 적용과 프론트엔드 배포를 같은 작업으로 진행한다. 운영 기록·회원가입 설정은 이번 구현에서 변경하지 않는다.
