# 보안·홈 화면 설치·운영 배포 점검

2026-11-16 · T-34 보안·설치 검증, T-35 운영 배포 및 실제 iPhone 확인 결과.

**운영 주소: https://baby-growth-tracker-5ib.pages.dev**

실제 서비스는 사용할 수 있다. T-35의 기록 1,000건·사진 100장 첫 표시 1초 목표는 아직 확인되지
않아 태스크 전체를 완료로 표시하지 않는다. 이 브랜치의 사진 목록 보완은 `main` 병합 후 배포된다.

## 구현한 내용

| 항목 | 적용 내용 |
| --- | --- |
| 보안 헤더 | `public/_headers`: 모든 정적 응답에 `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` |
| 설치 정보 | `public/manifest.webmanifest`: 고정 앱 ID·시작 주소·범위 `/`, 한국어, 이름·설명, `standalone` 표시 |
| 홈 화면 아이콘 | 앱 메뉴와 같은 Lucide 새싹·디자인 색상. PNG 192/512px, 불투명 Apple 180px, maskable 중앙 안전 영역. favicon도 새싹으로 통일 |
| iOS 정보 | HTML에 Apple 아이콘·앱 이름·단독 실행·상태 표시줄 설정 연결 |
| 개인정보 오류 출력 | React 루트와 Router 오류 콜백은 `reportUnexpectedError`를 공유한다. 원본 Error·cause·stack·기록 내용·서명 URL 대신 고정 문구만 출력한다. 화면은 기존 일반 오류 안내 유지 |
| 오프라인 | 설계 R22에 따라 Service Worker·오프라인 캐시를 추가하지 않는다. 홈 화면에 설치해도 데이터 이용에는 인터넷이 필요하다 |

아이콘은 미리 생성해 커밋한다. 빌드·CI에서 브라우저를 설치하거나 아이콘을 다시 만들지 않는다.
디자인 토큰 또는 Lucide 버전을 변경해 아이콘을 갱신할 때만 실행한다.

```bash
nvm use 24
npx playwright install chromium
npm run icons
# 설치된 Chrome을 쓸 때
npm run icons -- --chrome
```

Cloudflare Wrangler 4.162.0이 `_headers`의 유효한 규칙 1개를 읽었다. 다만 현재 macOS 13.3에서는
최소 13.5가 필요한 Workers 런타임이 실행되지 않았다. T-34 로컬 검증에서는 빌드된
`dist/_headers`를 같은 응답 헤더로 적용한 Vite 미리보기 서버를 사용했다. T-35에서 아래 실제
Cloudflare HTTPS 응답 검증까지 통과했다. 일반 `npm run dev`·`npm run preview`는 `_headers`를
자동 적용하지 않는다.

전체 `npm audit`에는 개발용 ESLint/TypeScript 검사 도구의 `minimatch` 관련 moderate 경고 9건이
남아 있다([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)). 운영 번들에는
포함되지 않는다. 자동 제안은 TypeScript 검사 도구의 버전 하향을 포함하므로 강제 적용하지 않았다.
개발 도구의 호환 가능한 수정 버전을 후속 유지보수에서 확인한다.

## 운영 설정과 재점검

| 대상 | 2026-11-16 적용 결과 |
| --- | --- |
| 프론트엔드 | Cloudflare Pages `baby-growth-tracker`, GitHub `oh-minyoung90/Baby-Growth-Tracker`의 `main` 연결 |
| 빌드 | Node 24, `npm run build`, `dist`. 운영 자동 배포 켜짐, 미리보기 배포 `none`, PR 자동 댓글 끔 |
| 첫 배포 | `main`의 `4fd2fae`(T-34 병합), 배포 `204f1cc6-8b4d-44b8-ad64-7847d8f5c8b7` 성공 |
| 운영 DB | Supabase Free `baby-growth-tracker-prod`, `emstzphokszsjumpjthc`, 서울 `ap-northeast-2` |
| DB·사진 | CLI로 마이그레이션 25개 적용·이력 일치, 테이블 12개 RLS 활성화, `recipe-photos` 비공개 |
| 계정 | 기존 dev 본인 이메일 1개만 등록, 테스트 A·B 제외. 서비스용 비밀번호를 직접 지정하지 않고 이메일 코드 사용 |
| 인증 | 신규 가입·익명 로그인 차단, 이메일 사용, 코드 6자리·600초, Site URL·허용 리디렉션은 운영 주소 |
| 메일 | Gmail SMTP·코드 템플릿 적용. 사용자가 운영 대시보드에 실제 앱 비밀번호를 직접 입력·저장한 뒤 iPhone 코드 수신 성공 |

SMTP의 Gmail은 **로그인 인증코드 발송용 계정**이다. 서비스에 로그인할 본인 이메일과 같을 필요는
없다. 앱 비밀번호는 Supabase 인증 설정에서만 관리하며 저장소·환경변수·문서에 넣지 않는다.
dev Auth에 보이는 보호된 SMTP 비밀번호 값을 복사하는 것으로 실제 앱 비밀번호 입력을 대체할 수 없다.

환경은 다음처럼 분리한다. dev의 기록·사진은 운영으로 자동 이전하지 않았다.

| 위치 | 용도 |
| --- | --- |
| `.env.local` | Sydney dev URL·Publishable key, 개발 서버 |
| `.env.test.local` | dev 테스트 A·B 및 `E2E_DEV_PROJECT_REF`, 자동 검증 |
| `.env.production.local` | 서울 prod URL·Publishable key만 저장, 로컬 운영 빌드용·권한 600·Git 제외 |
| Pages 운영 환경변수 | `NODE_VERSION=24`, prod `VITE_SUPABASE_URL`·`VITE_SUPABASE_PUBLISHABLE_KEY` |
| `deployment/production.json` | 운영 URL·프로젝트·브랜치·리전의 공개 메타데이터만 커밋 |

저장소 루트 Supabase CLI 연결은 계속 **dev**다. 최초 운영 마이그레이션은 별도 임시 작업 디렉터리에서
prod에 연결해 적용했다. 운영 DB 비밀번호는 macOS 키체인의 `Baby Growth Tracker deployment` /
`baby-growth-tracker-prod-db`에 보관했다. 이후 DB 변경도 dev 검증 후 **프론트엔드 배포 전에** 운영에
적용한다. 별도 작업 디렉터리에서 prod 대상·마이그레이션 목록을 먼저 확인하고 `supabase db push`를
실행한다. 루트에서 `npm run db:push`를 실행하면 dev에 적용되며, `supabase config push`는 사용하지 않는다.

배포 후 다음 명령으로 실제 운영 정적 응답을 확인한다.

```bash
nvm use 24
npm run check:production
```

`deployment/production.json`의 HTTPS 주소를 읽어 SPA 진입점·보안 헤더·MIME·manifest·PNG 실제 크기와
번들의 prod 연결/dev 미포함을 검사한다. API 키·로그인 세션·아이 데이터는 조회하지 않는다.
이 검사는 실제 코드 메일 수신·로그인·사진 업로드·기기 설치 확인을 대신하지 않는다.

## 대량 데이터 성능 점검과 남은 작업

운영 사용자 기록을 변경하지 않도록 dev 테스트 A의 원래 기록·사진을 보관한 뒤 가명 데이터로
검사하고 복구했다. 가명 발달 900건·키몸무게 100건, 레시피/사진 100개(각 JPEG 1280px·약 132KB)를
사용했다. 실제 Cloudflare 번들을 열되 브라우저에서 연결 URL·공개키만 Sydney dev로 바꾸고 운영 API
호출은 차단했다. 새 Chrome 컨텍스트, 네트워크/CPU 제한 없음, 데이터 조회·첫 항목/차트/사진 표시와
두 프레임까지 포함한 3회 중앙값이다.

| 화면 | 모바일 390px | PC 1440px |
| --- | --- | --- |
| 타임라인 | 1,808ms | 1,688ms |
| 키·몸무게 차트 | 2,170ms | 1,667ms |
| 레시피 첫 사진 | 2,556ms | 2,118ms |

**1초 목표 통과로 판단할 수 없다.** Sydney dev 지연·번들 응답 가로채기가 포함되어 서울 운영 환경의
동일 조건 측정을 대신하지 못한다. 운영 본인 데이터에 가명 1,000건을 덮어쓰지는 않는다.

추가 진단에서 화면 밖 사진까지 100개 메타데이터·서명을 동시에 요청하는 병목을 찾았다.
이 브랜치는 목록에서 화면 주변 200px 안으로 들어온 사진부터 메타데이터·서명을 요청한다.
사진 상세·편집은 즉시 조회하고 비공개 URL 만료 전 갱신·실패 안내를 유지한다.

로컬 운영 빌드 개선 전후를 같은 dev 데이터로 비교한 최초 사진 표시 시점의 메타데이터 조회 수:

| 화면 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 모바일 390px | 100개 | 3개 |
| PC 1440px | 100개 | 9개 |

두 화면에서 마지막 100번째 사진까지 스크롤해 실제 다운로드·표시도 확인했다. 이 비교는 요청 수를
검증하기 위한 것이며 1초 성능 인증이 아니다. 보완 코드의 `main` 병합·배포 후 운영 정적 점검을 다시
실행하고, 본인 운영 데이터와 분리된 환경에서 서울 리전·기록 1,000건·사진 100장 조건을 갖춰
목록·차트를 재측정하는 작업이 남아 있다. 이후 PRD 8장의 운영 최종 체크리스트를 점검한다.

T-35 코드 검증: 단위·컴포넌트 601개(57개 파일), lint·typecheck·format:check·build 통과.
dev DB를 사용하는 레시피·사진 E2E도 PC·모바일 2개 통과했으며 원래 기록·사진 복구를 확인했다.
운영 `check:production`도 통과했다. 빌드의 기존 500KB 초과 청크 안내는 남아 있다.
